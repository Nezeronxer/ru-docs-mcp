# VK API

## messages.send: всегда передавайте уникальный random_id
`random_id` - уникальный идентификатор, защищающий от повторной отправки. Ретрай с тем же random_id
не создаст дубль; без него (или с одинаковым на разные сообщения) получите дубли или проглоченные
сообщения. Берите id из своей БД или монотонный счётчик, а не `0`.
Источник: https://dev.vk.com/method/messages.send
Проверено: 2026-10-04

## peer_id беседы = 2000000000 + chat_id
Для беседы `peer_id` = `2000000000 + chat_id`, для сообщества - минус id сообщества, для
пользователя - его id. Путаница peer_id/chat_id - частая причина «сообщение ушло не туда».
Источник: https://dev.vk.com/method/messages.send
Проверено: 2026-10-04

## У методов разные типы токенов
У каждого метода в схеме указано, какие токены он принимает (`user`, `group`, `service`): например,
`messages.send` - user и group, `notifications.sendMessage` - только service. Ошибка доступа часто
означает не тот тип токена, а не нехватку прав - сверяйте строку «Токен» в описании метода.
Источник: https://dev.vk.com/method/messages.send
Проверено: 2026-10-04
