# Robokassa

## На ResultURL отвечать текстом OK{InvId}
Если подпись совпала, скрипт отвечает plain-текстом `OK` + номер счёта, например `OK5` для `InvId=5`.
Если подпись не совпала, уведомление считается некорректным. Фильтруете входящие по IP - добавьте в
белый список `185.59.216.65` и `185.59.217.65`.
Источник: https://docs.robokassa.ru/ru/notifications-and-redirects
Проверено: 2026-10-05

## Подпись ResultURL считается с Паролем #2, SuccessURL - с Паролем #1
ResultURL: `OutSum:InvId:Пароль#2[:Shp_*]`. SuccessURL: `OutSum:InvId:Пароль#1[:Shp_*]`. Статус заказа
меняйте по ResultURL: SuccessURL подходит для итоговой страницы, основное подтверждение приходит на ResultURL.
Источник: https://docs.robokassa.ru/ru/notifications-and-redirects
Проверено: 2026-10-05

## OutSum в уведомлении - строка с шестью знаками, подписывать как пришла
В боевом режиме `OutSum` имеет вид `100.000000`, в тестовом может быть с двумя знаками. В документации
база подписи собрана из полученной строки: `100.000000:450009:Пароль#2:Shp_login=Vasya:Shp_oplata=1`.
При создании платежа `OutSum` - число через точку (`123.45`).
Источник: https://docs.robokassa.ru/ru/notifications-and-redirects
Проверено: 2026-10-05

## В подписи запроса модификаторы идут в строгом порядке, Shp_* - после пароля
`MerchantLogin:OutSum:InvId:Receipt:StepByStep:ResultUrl2:SuccessUrl2:SuccessUrl2Method:FailUrl2:FailUrl2Method:Token:Пароль#1:Shp_*`
(берутся только переданные). Без `InvId` оставьте пустой слот `OutSum::...`. `Shp_*` сортируются по
алфавиту и чувствительны к регистру: `shp_item` вместо `Shp_item` даёт ошибку `29`.
Источник: https://docs.robokassa.ru/ru/pay-interface
Проверено: 2026-10-05

## Тестовый режим - только IsTest=1 и тестовые пароли
Без `IsTest=1` (или с `0`/пустым) платёж боевой. Подпись тестового запроса считается с тестовыми
Паролем #1 и #2 из «Технических настроек»: боевые пароли дают ошибку `29`. Тестовые `InvId` не
логируются и не вызывают ошибку `40` (повтор номера счёта).
Источник: https://docs.robokassa.ru/ru/testing-mode
Проверено: 2026-10-05

## В Receipt tax обязателен, сумма позиций равна сумме платежа, в подписи он URL-кодирован
`Receipt` - JSON; в строку подписи он попадает URL-кодированным, из-за объёма отправляйте `POST`.
В каждой позиции обязателен `tax`, `name` - до 128 символов. Сумма позиций равна сумме операции, в
рублях за всё количество с учётом скидок. Отсутствие номенклатуры - нарушение 54-ФЗ.
Источник: https://docs.robokassa.ru/ru/fiscalization
Проверено: 2026-10-05
