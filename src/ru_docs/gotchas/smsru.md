# SMS.ru

## Всегда ставьте json=1 и разбирайте результат по каждому номеру отдельно
С `json=1` ответ двухуровневый: верхний `status` значит лишь «запрос выполнен» (авторизация, отправитель),
а итог по каждому номеру лежит в `sms[<номер>]`: свой `status`/`status_code` (`100` - принято на отправку)
и `sms_id`. Проверяйте каждый номер и сохраняйте `sms_id`: он нужен для запроса статуса.
Источник: https://sms.ru/api/send
Проверено: 2026-10-05

## Код 100 - это «в очереди», доставку проверяйте по статусу или webhook
Код `100` значит «запрос выполнен или сообщение находится в очереди», а не «доставлено»: доставлено - `103`.
Итог узнавайте через webhook (`callback/add`) или `sms/status?sms_id=...&json=1`, а не по ответу `sms/send`.
Источник: https://sms.ru/api/status
Проверено: 2026-10-05

## test=1 имитирует отправку: сообщение не уходит и баланс не тратится
Параметр `test=1` нужен для проверки обработки ответов сервера: сообщение реально не отправляется,
баланс не расходуется. Не оставляйте его в боевом коде - иначе реальные SMS не уйдут.
Источник: https://sms.ru/api/send
Проверено: 2026-10-05

## Текст только в UTF-8, номера цифрами с кодом страны, больше 10 номеров - в теле POST
`msg` передавайте в UTF-8, иначе ошибка `212`. В примерах номера записаны цифрами с кодом страны без `+`: `to=79255070602`.
В `to` до 100 номеров через запятую; если номеров больше 10, передавайте `to` в теле POST, а не в адресной строке.
Неверный номер в списке даёт трёхзначный код ошибки вместо `sms_id`.
Источник: https://sms.ru/api/send
Проверено: 2026-10-05

## Перед sms/send ставьте captcha и передавайте в ip адрес пользователя, а не сервера
Метод без защиты от флуда позволяет обнулить баланс: ставьте captcha на страницах, где он вызывается
по действию пользователя, и передавайте в `ip` адрес пользователя (не сервера). Частный адрес (`192.*`, `10.*`)
даёт ошибку `507`; такую подсеть можно добавить в исключения в личном кабинете.
Источник: https://sms.ru/api/send
Проверено: 2026-10-05

## URL для callback/add: https:// и экранирование urlencode только в GET
Параметр `url` обработчика по описанию должен начинаться на `https://` (в таблице кодов у `901` написано
«не начинается на http://» - в документации разнобой, используйте https). В GET адрес экранируйте `urlencode`,
в POST экранировать не нужно.
Источник: https://sms.ru/api/callback_add
Проверено: 2026-10-05
