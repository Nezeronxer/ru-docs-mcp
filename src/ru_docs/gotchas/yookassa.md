# ЮKassa

## Уведомление (вебхук) не подписано - статус перепроверять запросом к API
У ЮKassa нет HMAC-подписи уведомлений. Документация велит проверять подлинность по статусу объекта
или по IP-адресу отправителя. Надёжный путь: получили `payment.succeeded` - сделайте
`GET /v3/payments/{id}` и выдавайте товар только по статусу, сумме и metadata из ответа API,
а не из тела уведомления. Поддельный POST на ваш URL иначе «оплатит» заказ.
Источник: https://yookassa.ru/developers/using-api/webhooks
Проверено: 2026-10-04

## На уведомление отвечать HTTP 200, иначе повторы 24 часа
ЮKassa игнорирует тело ответа, важен только код 200. Любой другой код - уведомление
доставляется повторно в течение 24 часов. Значит, обработчик должен быть идемпотентным: одно и то же
`payment.succeeded` может прийти несколько раз - не начисляйте дважды.
Источник: https://yookassa.ru/developers/using-api/webhooks
Проверено: 2026-10-04

## Idempotence-Key обязателен для POST и DELETE, живёт 24 часа
Заголовок `Idempotence-Key` (до 64 символов, рекомендован UUID v4) нужен на каждом POST/DELETE.
Повтор с тем же ключом и теми же данными вернёт результат первого запроса; тот же запрос с новым
ключом создаст второй платёж. Через 24 часа ключ «забывается». Генерируйте ключ от своего id заказа
(например uuid5), а не случайно на каждый ретрай - иначе ретрай после обрыва сети создаст дубль.
Источник: https://yookassa.ru/developers/using-api/interaction-format
Проверено: 2026-10-04

## Сумма - строка в рублях с двумя знаками, не копейки
`"amount": {"value": "100.00", "currency": "RUB"}` - строка, точка, ровно два знака после неё.
Не `10000` (копейки, как у Т-Банка) и не float `100.0` - float ещё и даёт ошибки округления.
Считайте в копейках целыми, а в API отдавайте `f"{kop // 100}.{kop % 100:02d}"`.
Источник: https://yookassa.ru/developers/api
Проверено: 2026-10-04

## Двухстадийный платёж сам отменится, если не списать
При `capture: false` платёж уходит в `waiting_for_capture`. Если не вызвать capture или cancel за
отведённое время (зависит от способа оплаты), он перейдёт в `canceled`, деньги вернутся покупателю.
Нужен фоновый процесс, который подтверждает или отменяет такие платежи. Для простого магазина -
`capture: true`.
Источник: https://yookassa.ru/developers/payment-acceptance/getting-started/payment-process
Проверено: 2026-10-04

## Возврат на return_url - не доказательство оплаты
После оплаты пользователь возвращается на `return_url`, но статус платежа может быть ещё `pending`
или `canceled`. Статус берите из API (`GET /v3/payments/{id}`) или вебхука. Если у бота нет
вебсервера (long polling), статус узнают периодическим опросом платежа.
Источник: https://yookassa.ru/developers/payment-acceptance/getting-started/payment-process
Проверено: 2026-10-04

## Тестовый магазин - отдельные shopId и ключ, настоящие карты не работают
Тестовый магазин создаётся отдельно (можно до регистрации) и имеет свои идентификатор и секретный
ключ. Настоящие карты в нём не проходят - только тестовые, например `5555 5555 5555 4477`.
Ключи тестового магазина не работают в боевом и наоборот.
Источник: https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing
Проверено: 2026-10-04

## Платёж через Telegram-виджет даёт только карту
Встроенные платежи Telegram (`sendInvoice` с provider_token ЮKassa) - это оплата картой. Нужны СБП,
SberPay, ЮMoney - создавайте платёж через API v3 с `confirmation.type = redirect` и отправляйте
пользователю `confirmation_url` кнопкой.
Источник: https://yookassa.ru/developers/payment-acceptance/getting-started/payment-methods
Проверено: 2026-10-04 (на реальном боте)
