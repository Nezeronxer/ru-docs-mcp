# ЮMoney (кошелёк, HTTP-уведомления, формы)

## Подпись уведомления - поле sign (HMAC-SHA256), sha1_hash уходит
Проверять нужно `sign`: HMAC-SHA256 с секретом из настроек HTTP-уведомлений, результат в HEX нижнего
регистра. Параметр `sha1_hash` устарел и перестаёт приходить с 18 мая 2026, после этой даты по нему
проверять нечего.
Источник: https://yoomoney.ru/docs/wallet/using-api/notification-p2p-incoming
Проверено: 2026-10-05

## Строка для подписи: все поля кроме sign, по алфавиту, значения в URL-кодировке
Уберите `sign`, отсортируйте остальные параметры по алфавиту (A-Z), значения URL-кодируйте (UTF-8,
RFC 3986), склейте `ключ=значение` через `&`. Пустое значение остаётся как `key=`, без пробелов.
Источник: https://yoomoney.ru/docs/wallet/using-api/notification-p2p-incoming
Проверено: 2026-10-05

## Отвечать надо HTTP 200: попыток доставки три
Принятым считается только ответ `200 OK`. ЮMoney пробует доставить уведомление трижды: сразу, через
10 минут и через час. Тестовые уведомления помечены флагом `test_notification`, у настоящих его по
умолчанию нет.
Источник: https://yoomoney.ru/docs/wallet/using-api/notification-p2p-incoming
Проверено: 2026-10-05

## В форме sum списывается с отправителя, получателю приходит меньше на комиссию
`sum` - сумма списания; комиссия берётся с получателя: `PC` (кошелёк) 1%, `AC` (карта) 3%, с карты
1000 руб. дойдёт 970. В уведомлении `amount` - зачислено получателю, `withdraw_amount` - списано у
отправителя, так что с ценой заказа сверяйте `withdraw_amount`.
Источник: https://yoomoney.ru/docs/payment-buttons/using-api/forms
Проверено: 2026-10-05

## access_token живёт 3 года, код авторизации одноразовый, redirect_uri сверяется посимвольно
Обмен кода на токен вернёт `invalid_grant`, если код просрочен или по нему уже выдан токен.
`redirect_uri` в `/oauth/token` должен побуквенно совпасть с переданным в `authorize`. Токены,
полученные после 7 февраля 2018, действуют 3 года (до этой даты - 6 месяцев).
Источник: https://yoomoney.ru/docs/wallet/using-api/authorization/obtain-access-token
Проверено: 2026-10-05

## process-payment: при in_progress или без ответа повторяйте тот же вызов
`in_progress` значит, что авторизация не завершена: повторяйте `process-payment` с теми же
параметрами раз в минуту до `success` или `refused`. Если ответа нет вообще, платёж равновероятно
прошёл или нет - тоже повтор. После 3-D Secure повторный вызов делается только с `request_id`.
Источник: https://yoomoney.ru/docs/wallet/process-payments/process-payment
Проверено: 2026-10-05
